# Источники и проверка опций

Дата: 28.10.2026.

| Источник | Использование |
|---|---|
| https://iperf2.sourceforge.io/iperf2-user-manual.html | isochronous, IPG, burst; онлайн-версия отличается от установленной 2.1.9 |
| https://software.es.net/iperf/invoking.html | UDP bitrate/pacing, TCP `-n`, размер блока; онлайн-документация 3.22, измеряемая версия 3.16 |
| https://portal.3gpp.org/desktopmodules/Specifications/SpecificationDetails.aspx?specificationId=2493 | карточка TR 36.814, Release 9 |
| TR 36.814 V9.0.0, A.2.1.3.1, Table A.2.1.3.1-2, p.75 | Model 2: 0,5 Mbytes; exponential reading time, mean 5 s; K fixed; пауза от конца предыдущей загрузки до следующего запроса |

Первичная карточка 3GPP прочитана. Прямые загрузки PDF с ETSI и ZIP с 3GPP вернули HTTP 403. Параметры таблицы сверены по индексированному тексту документа TR 36.814 V9.0.0, найденному поиском по зеркалу `https://www.freecalypso.org/pub/GSM/3GPP/archive/36_series/36.814/36814-900.pdf`; прямой адрес зеркала при повторном открытии вернул 404. Копия полного стандарта не включена; успешная загрузка первичного документа не заявляется. Для нормативного использования следует самостоятельно получить оригинал TR по карточке 3GPP. Другие модели и пересказы с противоречивыми средними временами не использовались.

Приоритет для команд: фактический бинарник → parser/help → короткий реальный тест → захват. Локальные `iperf2-help.txt`, `iperf3-help.txt`, `iperf2-man.txt` сохранены. `--burst-period` и `--burst-size` есть в man, но не перечислены в help 2.1.9; их принятие проверено отдельными parser-probe JSON. Одно принятие опции не доказывает её влияние на UDP.

В локальном `iperf2 --help` IPG указан в миллисекундах, в man и актуальном web manual — в секундах. PCAP-проба показала, что `--ipg 0.96` даёт медиану около 0,960 мс; `--ipg 0.00096` — микросекундные пачки. Это результат для версии 2.1.9, а не универсальное правило для iPerf2.
